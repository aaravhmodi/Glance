**What to pitch:** per-block quality is the only method that wins on video calls: about +3 dB where the viewer looks at the same bitrate, or about half the bitrate at the same foveal quality. It needs a native encoder; no shipped browser API exposes per-region quality (docs/research.md §8). The browser demo shows the blur method.

**Skeptic findings (`offline/experiments/skeptic.py --all`, `results/raw/skeptic.json`):**
- Measurement and baseline fairness confirmed (independent scorer agrees within 0.005 dB; identical encoder command for both streams).
- The blur method's loss on call clips comes from the synthetic trace jumping every 0.2–0.6 s. With a fixed gaze or a calm call-like trace it wins by about 1 dB (2 clips, 300–1000 kbps); with the jumpy trace it loses everywhere.
- Busy-content gains at ≤1000 kbps are mostly fewer frozen frames (the baseline drops 50–86 of 90 frames there). Counting only frames both streams encoded: river +3.59 → +0.23 dB, spreadsheet +3.04 → +0.61 dB. At 4000 kbps (almost no drops) the gain is real: +2.77 and +4.61 dB. The equal-quality savings above have about the same drop counts in both streams.
- Scoring over a disc 1.5× the fovea radius makes the blur method lose even with a fixed gaze (+1.08 → −2.87 dB): just outside the fovea it is clearly worse.
- A bug was found and fixed: on ffmpeg 8 the pre-filter corrupted tagged mp4 clips (regression test added). With the fix the laptop reproduces the server's call-clip numbers.

## T8 result (14 Nov; synthetic gaze, 3 call clips, 720p, VP9 CBR realtime, 150 / 90 frames)
Reproduce: `python3 offline/experiments/run.py --t8` (~35 min). Raw: `results/raw/exp_transport.json`, `exp_tracker.json`. Tests: `python3 -m unittest discover -s offline/experiments -p "test_*.py"` (24 green); smoke green.
- **Transport model** (2 % packet loss, jitter buffer 100 ms, 1200 B packets, no retransmission, freeze until next keyframe every 2 s; 4 seeds; same draws for both streams; equal CBR cap): ~80-92 % of frames are frozen for BOTH streams, so the model is very pessimistic and mostly measures freezes. Foveal PSNR gain of Glance over baseline (dB, clean network / lossy): desk 500: -2.60 / -0.80; desk 1000: -1.55 / -3.21; plants 500: -0.88 / +2.78; plants 1000: -0.43 / -0.24; teacher 500: -0.82 / +0.54; teacher 1000: -0.09 / +0.84. Mixed, inside the noise of 4 seeds; no claim. Glance has slightly fewer packets, hence slightly fewer loss chances (real effect of fewer bytes, but tiny at CBR where both fill the cap).
- **Tracker error** (fovea centre = true gaze 100 ms old + AR(1) noise with mean radial error 0/2/4/6°; scored at the TRUE gaze, 5° disc; baseline same cap): Glance loses everywhere. Foveal PSNR gain, fixed 5° radius: desk 500 kbps -5.7 / -6.8 / -8.8 / -10.8 dB at 0/2/4/6°; desk 1000: -5.3 / -6.8 / -9.8 / -12.3; teacher 500: -3.9 / -4.7 / -7.0 / -9.2. Sigma-adaptive radius (radius grows with the error): desk 500 -5.9 / -5.1 / -3.9 (2/4/6°), teacher 500 -4.1 / -3.2 / -2.0: smaller loss, never a win. Note the "0°" row has 100 ms lag only, which alone gives a realised 2.9° mean error (saccades). Realised mean errors (incl. lag): 2.9 / 4.1 / 5.5 / 7.0°.
- Takeaway: with a 5° fovea, 100 ms lag and webcam-grade error the pre-filter-only Glance is worse than the plain stream at equal bitrate on these clips. It needs a bigger/adaptive fovea, and the encoder-side loss from T7a (below) still applies.

Skeptic substitute: I re-ran call-teacher 500 kbps 6° (fixed and adaptive) from scratch: gain -9.195 / -2.044 dB, identical to the stored rows.
